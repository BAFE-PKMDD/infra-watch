InfraWatch Methodology documentation

Data dictionary and schedule methodology

Terms, fields, computations, and classification details

This reference explains how InfraWatch derives target completion, expected progress, schedule gap, delayed and at-risk classifications, and how ABEMIS API fields are stored, derived, and used across pages.

Effective reference: 27 August 2026 Date basis: Asia/Manila calendar dates Scope: ABEMIS-backed public and administrative project pages

1. Overview

InfraWatch uses deterministic rules for its schedule status. The classification is not generated by AI and does not represent an engineering certification. It compares reported dates and reported physical progress against a simple assumption: work advances evenly from the recorded project start date to the target completion date.

Important interpretation “Expected progress” is a schedule comparison baseline. It is not the contractor’s official Program of Work curve, and it is not a prediction of the date on which construction will finish.

2. Source inputs

The schedule computation depends on these fields synchronized from ABEMIS:

InputHow InfraWatch obtains itUse
Start date / NTP date The first procurement milestone containing “Notice to Proceed”; the actual date is preferred, otherwise its target date is used. Beginning of the project schedule.
Calendar days The reported calendar_days value, parsed as a number and rounded to the nearest whole day. Contract duration used to derive target completion.
Actual physical progress Numeric actual values from Program of Work (POW) rows are added, rounded, and constrained to 0–100% during import. Compared with expected progress.
Project status The source status/stage is normalized into planned, ongoing, completed, or suspended. Determines whether an active schedule comparison is appropriate.
As-of date The dashboard’s reporting date, evaluated as a calendar date in Asia/Manila. Represents “today” in all schedule calculations.

A stored zero is not treated as proof of reported progress by itself. The dashboard checks for at least one numeric POW actual value before treating physical progress as available evidence.

3. How Target Completion is computed

Target Completion is derived from the Notice to Proceed date and the reported contract duration. It is not independently estimated by InfraWatch.

Target Completion Date = NTP Start Date + Calendar Days
  1. Find the first procurement milestone whose name contains “Notice to Proceed.”
  2. Use its actual date. If the actual date is absent, use its target date.
  3. Parse and round the reported calendar-day duration to a whole number.
  4. Add that duration to the NTP date using calendar days.

Example: target completion

NTP date: 1 July 2026  ·  Contract duration: 90 calendar days

Target Completion = 29 September 2026.

If the NTP date or calendar days are missing, Target Completion cannot be computed. A schedule whose target is the same as or earlier than its start is treated as invalid for schedule assessment.

4. How “Expected by now” is computed

Expected progress is the share of the contract duration that has elapsed as of the reporting date. The value is limited to the range 0–100%.

Duration Days = Target Completion Date − Start Date
Elapsed Days = As-of Date − Start Date
Expected Progress (%) = clamp(0, 100, Elapsed Days ÷ Duration Days × 100)

The calculation uses date-only Manila calendar boundaries. If the start is in the future, either schedule date is missing, or duration is zero/negative, Expected Progress is not assessed.

5. What Schedule Gap means

Schedule Gap is the difference between reported actual physical progress and the progress expected by the current date under the even-progress assumption.

Schedule Gap (percentage points) = Actual Physical Progress − Expected Progress
  • Positive gap: reported work is ahead of the even schedule baseline.
  • Zero gap: reported work is exactly at the expected pace.
  • Negative gap: reported work is behind the expected pace.
Percentage points, not percent change If actual progress is 32% and expected progress is 50%, the Schedule Gap is −18 percentage points. It is not described as “18% behind.”

In the dashboard, Schedule Gap is displayed only when both actual progress evidence and a valid active schedule comparison are available. Delayed, completed, inactive, or unassessable records may show no gap.

6. How schedule status is classified

Rules are evaluated in the following order. An earlier matching rule takes precedence.

Cannot be assessed
Used for completed projects; missing or invalid schedule dates; future starts; inactive/non-ongoing projects that are not already past target; missing progress evidence; or progress outside 0–100%. Completed-late history may be recorded separately, but a completed project is not counted as an active delay.
Delayed
The project is not completed, has a valid schedule, and its Target Completion Date is earlier than the as-of date. The target date itself is not late; delay begins on the following Manila calendar day.
At risk of delay
For an ongoing project that is not yet past target, either (a) actual progress is at least 15 percentage points behind expected progress, or (b) the target is 0–30 days away inclusive and actual progress is below 80%.
On schedule
The project is ongoing, assessable, not past target, less than 15 percentage points behind the expected pace, and does not meet the due-soon/low-progress rule.

Threshold details

RuleBoundaryInterpretation
Past targettarget date < as-of dateStrictly earlier; one day past target is delayed.

Due soon0 ≤ days to target ≤ 30Includes the target date and exactly 30 days before it.

7. Worked examples

Example A: at risk because of a schedule deficit

Start: 1 July 2026  ·  Target: 29 September 2026  ·  As of: 15 August 2026

Duration = 90 days; elapsed = 45 days; expected = 45 ÷ 90 × 100 = 50%.

Actual = 32%; Schedule Gap = 32 − 50 = −18 percentage points.

Result: At risk of delay, because the deficit is at least 15 percentage points.

Example B: at risk because completion is due soon

Start: 8 May 2026  ·  Target: 5 September 2026  ·  As of: 15 August 2026

Expected = 82.5%; actual = 75%; Schedule Gap = −7.5 percentage points.

The gap alone is below the 15-point threshold, but the target is 21 days away and actual progress is below 80%.

Result: At risk of delay.

Example C: delayed

Target: 1 August 2026  ·  As of: 10 August 2026  ·  Project is not completed.

Days to target = 1 August − 10 August = −9 days.

Result: Delayed, because the target date has passed.

8. Target Completion vs Projected Completion

These are different values and should not be used interchangeably:

TermMeaningMethod
Target Completion The schedule date derived from NTP plus reported calendar days. Contract-schedule arithmetic; it does not use observed work velocity.
Projected Completion A forecast based on the trend in historical physical-progress snapshots. Linear regression; requires at least 3 valid daily snapshots spanning at least 14 days and a positive progress slope.

For a valid forecast, InfraWatch estimates progress velocity in percentage points per day and calculates the remaining days needed to reach 100%. A projected date later than Target Completion is flagged as target risk. Stalled, completed, inactive, or insufficient-history projects do not receive a projected completion date.

9. Data and interpretation limitations

  • Results depend on the accuracy and freshness of ABEMIS dates, statuses, calendar days, and POW progress.
  • The even-progress baseline does not model mobilization, weather, sequencing, milestone weights, approved extensions, suspensions, or a project-specific S-curve.
  • A “Cannot be assessed” result is a disclosure of insufficient or inapplicable inputs, not evidence that the project is on schedule.
  • “At risk” is an analytical early-warning classification, not a formal finding of contractor default.
  • “Delayed” means an incomplete record is past its stored target date. It does not, by itself, determine cause, liability, or whether a time extension is pending.
  • Source corrections can change historical classifications after synchronization.

10. Glossary

Actual Physical Progress
Reported completion percentage derived from numeric POW actual values.
As-of Date
The Manila calendar date against which the dashboard evaluates schedule health.
Calendar Days
The reported whole-day contract duration; weekends and holidays are not removed by this arithmetic.
Days to Target
Target Completion Date minus As-of Date. Positive means days remaining; zero means due today; negative means days past target.
Expected Progress / Target Today
The linearly elapsed share of the recorded start-to-target period.
NTP
Notice to Proceed, used as the schedule start date.
Schedule Gap / Variance
Actual progress minus expected progress, expressed in percentage points.

11. How ABEMIS fields flow into InfraWatch

InfraWatch reads infrastructure records from the ABEMIS endpoint /api/infra-amefip-list. The API uses snake-case field names such as project_title and allocated_amount. During synchronization, InfraWatch validates, normalizes, or derives those values and stores them in its local projects table. Pages read the local database; they do not call ABEMIS separately on every page view.

Example: what “status = ongoing” means

ABEMIS sends status: "Ongoing".

Import normalization trims and lowercases it, then stores projects.status = "ongoing".

The public directory/detail label becomes On going. The managerial dashboard canonical status is ongoing.

If valid start/target dates and physical-progress evidence exist, the project can then be classified as On schedule, At risk of delay, or Delayed. “Ongoing” alone does not determine schedule health.
